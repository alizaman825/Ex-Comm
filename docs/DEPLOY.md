# Deployment

Backend (Express API) on **Render**, frontend (Next.js) on **Vercel**, database on **MongoDB Atlas**.

The browser only talks to the Vercel site. Next.js proxies `/api/*` to the Render API (`BACKEND_URL`), so the session cookie stays first-party.

## 1. Backend on Render

1. Render dashboard → New → Blueprint → pick this repository. `render.yaml` creates the `ex-comm-api` web service (root `backend`, health check `/api/health`).
2. Fill in the two prompted values:
   - `MONGO_URI`: the Atlas connection string (database `excomm`).
   - `CORS_ORIGIN`: the Vercel URL from step 2 (it can be updated after the first deploy).
3. `JWT_SECRET` and `JOB_KEY` are generated by Render. The first start seeds sample data (about a minute).
4. Check: `https://<service>.onrender.com/api/health`.

Free instances sleep after 15 minutes idle; the first request after that takes about a minute.

## 2. Frontend on Vercel

1. Vercel → Add New → Project → import this repository.
2. Root Directory: `frontend` (framework preset Next.js is detected).
3. Environment variable: `BACKEND_URL=https://<service>.onrender.com`.
4. Deploy, then put the resulting `https://<project>.vercel.app` into Render's `CORS_ORIGIN`.

## 3. Atlas network access

Render's free plan has no fixed outbound IP, so allow `0.0.0.0/0` under Atlas → Network Access and rely on a strong database user password.

## Notes

- `TRUST_PROXY=2` makes rate limits see the visitor's IP behind the Vercel rewrite and Render's proxy.
- Demo login after seeding: demo@excomm.pk / demo1234.
